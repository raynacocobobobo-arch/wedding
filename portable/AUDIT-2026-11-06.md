## 已修正的实际问题

1. 腾讯云 ZIP 使用 base=/wedding/，但上传包的 server.mjs 无 /wedding/* 处理，直接打开子路径可能404。GitHub portable 服务端现统一处理 /wedding/*，兼容原始根路径。
2. 前后台上传图片的数据库路径以 /uploads/ 开头，必须在前端与 base 一起正确解析。前端和后台现在均使用相对资源路径。
3. 服务端 CSP 的 base-uri 原先为 none，会与 HTML base 标签冲突，现改为 self。
4. 反向代理部署会使客户端 IP 看似都是127.0.0.1，导致咨询或登录限流误伤。增加仅信任本机反代的 TRUST_PROXY 选项与 X-Real-IP 校验；必须由可信 Nginx/Caddy 覆盖对应头。
5. 防止未发布作品的已上传照片仅凭 URL 被公开读取；发布后可供公众浏览，下架后再次受保护。
6. 把咨询元数据持久化记录、企微失败重试、联系资料环境变量写入部署说明。注意私有信息及备份要求。

## 尚未完成，不应宣称完成

- 真实企业微信群机器人的通知送达验证，必须在腾讯云私有 .env 配置实际 WECOM_WEBHOOK 并用测试咨询确认。
- Tencent COS 接入：目前 portable 后端仍写入 data/uploads，本地目录若部署在腾讯云云服务器上属于云服务器磁盘存储，不等于 COS。需单独实施 COS SDK / 对象密钥、权限和生命周期管理。
- 实际腾讯云 Nginx/HTTPS 反向代理、持久卷、自动备份与发布验收。
- 与根目录 V5.1 视觉完全一致；本次不重做页面布局，仅避免新增功能误改现有布局。

## 正式部署前检查

1. 先备份运行中的 .env 和 data/（包括 works.json、uploads/、inquiries.json）。
2. 腾讯云 Agent 从 GitHub 拉取最新 main 分支的 portable/，保留已有子路径 /wedding/。
3. 设置 HOST、PORT、COOKIE_SECURE、TRUST_PROXY、WECOM_WEBHOOK、CONTACT_*，切勿将密钥提交仓库。
4. 运行 npm test，部署后验证 /wedding/、/wedding/admin、图片上传、咨询表单、首页展示及企微群通知。
5. 不影响当前 GitHub Pages V5.1 展示站及其他 DND 项目。
